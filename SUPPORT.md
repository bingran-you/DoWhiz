# Support

## What This Document Covers

This repository is open source, but maintainer support is limited.

Use this file to decide where to ask for help and what kind of response to expect.

## Where To Ask

### Bug Reports

Open a GitHub issue with:
- the relevant issue template
- exact reproduction steps
- expected vs actual behavior
- logs or screenshots when useful

### Feature Requests

Open a GitHub issue with the feature-request template.

### Security Problems

Do not file a public issue. Follow [SECURITY.md](SECURITY.md).

## What Maintainers Can Usually Help With

- problems in the public demo path
- inaccuracies in public docs
- contributor workflow issues
- public CI failures
- scoped bugs in supported open-source paths

## What Maintainers May Not Be Able To Help With

- private Azure, Supabase, Postmark, or other vendor-account setup
- production parity with the internal DoWhiz environment
- custom downstream deployments
- every third-party integration in every provider mode
- urgent support or SLA-backed responses

## Support Expectations

Support is best effort.

That means:
- maintainers may batch issue triage
- not every question gets a same-day response
- issues without reproduction steps may be closed until more detail is available
- out-of-scope operational questions may be redirected to documentation instead of debugged one-on-one

## Good Issue Hygiene

Before opening an issue:

1. Read [README.md](README.md).
2. Check [OPEN_SOURCE_SCOPE.md](OPEN_SOURCE_SCOPE.md).
3. Review [docs/README.md](docs/README.md).
4. Confirm the problem is reproducible on the current branch you are using.
