# Oliver Readiness Brief Reviewer Checklist

Use this checklist when judging whether a single readiness brief is actually decision-useful.

## Core Test

- [ ] The brief identifies the real launch goal, not just generic activity.
- [ ] The brief separates blockers from dependencies and from open decisions.
- [ ] The brief identifies who matters next.
- [ ] The dates or launch window reflect what the thread actually supports.
- [ ] The readiness color feels earned by visible evidence.

## Hallucination Checks

- [ ] No owner was invented from a team name, function, or vague mention.
- [ ] No firm date was invented when the thread only gave a window or placeholder.
- [ ] No blocker was invented from a normal open task.
- [ ] No false certainty was added where the thread stayed incomplete or conflicted.

## Usefulness Checks

- [ ] I can tell what I should do next without rereading the whole thread first.
- [ ] The tracker would help me prep for a launch review or status meeting.
- [ ] The follow-up target selection is sensible.
- [ ] At least one draft follow-up is close enough to approve with light edits.
- [ ] The brief surfaced something operationally important that a plain summary could miss.

## Weak-Signal Checks

- [ ] On incomplete threads, the brief stays sparse instead of pretending there is a full plan.
- [ ] The output explicitly says what is still unknown.
- [ ] The system avoids creating noisy follow-up drafts when the thread is not ready for them.

## Verdict

- [ ] I would trust this brief enough to use it in a real execution workflow.
- [ ] I would approve/send at least one drafted follow-up.
- [ ] I would give Oliver another thread after seeing this result.
